# 构建遵循最佳实践的登录表单

利用跨平台浏览器特性，构建安全、无障碍且易用的登录表单。

只要用户需要登录你的网站，良好的登录表单设计就至关重要。对于网络连接差、使用移动设备、赶时间或处于压力下的用户尤其如此。设计糟糕的登录表单会导致高跳出率。每一次跳出都可能意味着失去一位客户和一位不满的用户——而不仅仅是错过一次登录机会。

## 如何实现

以下列出了构建成功登录表单的最重要准则。

### 使用有意义、有效的 HTML

充分利用为创建表单而构建的元素和属性：

- `<form>`、`<input>`、`<label>` 和 `<button>`
- `type`、`autocomplete` 和 `inputmode`

这些能启用浏览器内置功能、改善无障碍性，并为标记增添语义。

### 使用 `<label>` 元素为数据输入的表单字段添加标签

要为 `<input>`、`<select>` 或 `<textarea>` 添加标签，请使用 `<label>`。将标签的 `for` 属性设置为与输入的 `id` 相同的值，即可将标签与输入关联。

### 充分利用 HTML 属性

通过使用带有 `type` 属性的适当 `<input>` 元素，让用户轻松输入数据，从而在移动设备上提供正确的键盘，并启用浏览器内置的基本验证。

电子邮件地址始终使用 `type="email"`，电话号码始终使用 `type="tel"`。

每个 `<input>`、`<select>` 和 `<textarea>` 元素都应具有适当的 `autocomplete` 属性，以改善无障碍性并帮助用户避免重复输入数据。

用户名和电子邮件输入包含的是标识符，而非普通文本。添加 `spellcheck="false"`，以免浏览器将其改写为与账户不匹配的内容。对于 `input type="email"`，`autocorrect` 和 `autocapitalize` 始终处于禁用状态，但对于非电子邮件用户名则需要设置。

### 让按钮更有帮助

按钮请使用 `<button>`。你也可以使用 `<input type="submit">`，但不要使用 `div` 或其他随意元素充当按钮。按钮元素提供无障碍行为、内置表单提交功能，且易于样式化。

为每个表单提交按钮赋予能说明其作用的值。使用清晰、可识别的标签。例如，使用 **登录** 而非 **继续** 或 **提交**。

### 尽可能使用单一姓名输入

允许用户使用单个输入输入姓名，除非你有充分理由分别存储名、姓、称谓或其他姓名部分。使用单一姓名输入可使表单更简单、支持剪切粘贴，并使自动填充更简单。为姓名的单一输入使用 `autocomplete="name"`。

```html
<input type="text" id="fullname" name="fullname" autocomplete="name">
```

允许国际姓名。验证时，避免使用仅匹配拉丁字符的正则表达式。仅限拉丁字符会排除姓名或地址包含非拉丁字母字符的用户。改为允许 Unicode 字母匹配——并确保后端在输入和输出时都能安全支持 Unicode。现代浏览器对正则表达式中的 Unicode 有良好支持。

### 显示登录进度

对于登录的每个步骤，使用页面标题和描述性按钮值，清楚说明当前需要做什么以及下一步是什么。

在表单输入上使用 `enterkeyhint` 属性设置移动键盘回车键标签。例如，在多页表单中使用 `enterkeyhint="previous"` 和 `enterkeyhint="next"`，表单最后一个输入使用 `enterkeyhint="done"`，搜索输入使用 `enterkeyhint="search"`。

### 帮助用户避免重复输入登录数据

确保在登录表单中添加适当的 `autocomplete` 值。

这使浏览器能够安全存储登录详情并正确填写表单数据，从而帮助用户。没有 autocomplete，用户可能更倾向于保留登录详情的物理记录，或在其设备上不安全地存储登录数据。

### 谨慎验证

在实时和表单提交前都验证数据输入。电子邮件输入使用 `type="email"`——浏览器会自动验证格式。为必填字段添加 `required` 属性以防止空提交。

### 将登录放在独立的 `<form>` 元素中

在让用户输入数据时，始终使用 `<form>` 元素

不要将输入包裹在 `<div>` 中并纯粹用 JavaScript 处理输入数据提交。通常最好使用 `<form>` 元素。这使你的网站对屏幕阅读器和其他辅助设备无障碍、启用一系列浏览器内置功能、更简单地构建对旧版浏览器可用的基本登录功能，并且即使 JavaScript 失败也仍能工作。

### 不要重复输入

有些网站强制用户输入两次电子邮件或密码。这可能减少少数用户的错误，但会给所有用户带来额外工作，并增加放弃率。在浏览器自动填充电子邮件地址或建议强密码的情况下，要求输入两次也毫无意义。更好的做法是让用户确认其电子邮件地址（无论如何你都需要这样做），并在必要时让他们轻松重置密码。

### 保持密码私密——但允许用户按需查看

密码输入应使用 `type="password"` 以隐藏密码文本，并帮助浏览器理解该输入用于密码。（注意，浏览器使用多种技术来理解输入角色并决定是否提供保存密码。）

你应添加 **显示密码** 切换，让用户能检查已输入的文本——别忘了添加 **忘记密码** 链接。

### 为移动用户提供正确的键盘

使用 `<input type="email">` 为移动用户提供适当的键盘，并启用浏览器内置的基本电子邮件地址验证……无需 JavaScript！

如果你需要使用电话号码而非电子邮件地址，`<input type="tel">` 可在移动设备上启用电话键盘。你还可以在必要时使用 `inputmode` 属性：`inputmode="numeric"` 非常适合 PIN 码。

### 防止移动键盘遮挡登录按钮

如果不小心，移动键盘可能会覆盖你的表单，或更糟的是，部分遮挡登录按钮。用户可能在意识到发生了什么之前就放弃了。

尽可能避免这种情况：在登录页面顶部仅显示电子邮件（或电话）和密码输入以及登录按钮。将其他内容放在下方。

### 帮助用户避免重复输入数据

你可以帮助浏览器正确存储数据并自动填充输入，这样用户就不必记住输入电子邮件和密码值。这在移动设备上尤为重要，对电子邮件输入更是关键，因为其放弃率很高。这包括两部分：

1.  `autocomplete`、`name`、`id` 和 `type` 属性帮助浏览器理解输入的角色，以便存储数据供后续自动填充使用。为允许存储数据用于自动填充，现代浏览器还要求输入具有稳定的 `name` 或 `id` 值（而非在每次页面加载或站点部署时随机生成），并且位于带有 `submit` 按钮的 `<form>` 元素中。
1.  `autocomplete` 属性帮助浏览器使用存储的数据正确自动填充输入。

对于电子邮件输入，使用 `autocomplete="username"`，因为 `username` 会被现代浏览器中的密码管理器识别——即使你应使用 `type="email"`，并且可能想使用 `id="email"` 和 `name="email"`。对于密码输入，使用适当的 `autocomplete` 值帮助浏览器区分新密码和当前密码（分别为 `autocomplete="new-password"` 和 `autocomplete="current-password"`）。

### 为现有密码使用 autocomplete="current-password"

强制要求：在登录表单的密码输入中使用 `autocomplete="current-password"`。这告诉浏览器你希望它使用其为该站点存储的当前密码。

对于登录表单：

```
<input type="password" autocomplete="current-password" id="current-password" …>
```

### 让浏览器能够建议强密码

现代浏览器使用启发式方法决定何时显示密码管理器 UI 并建议强密码。

浏览器内置的密码生成器意味着用户和开发者无需弄清楚什么是"强密码"。由于浏览器可以安全存储密码并在需要时自动填充，用户无需记住或输入密码。鼓励用户利用浏览器内置的密码生成器，也意味着他们更可能在你的网站上使用唯一、强密码，而不太可能重复使用可能在其他地方已泄露的密码。

### 帮助用户避免意外遗漏输入

强制要求：为电子邮件和密码字段都添加 `required` 属性。现代浏览器会自动提示并聚焦缺失的数据。

```html
<input type="email" id="email" name="email" autocomplete="username" required>
<input type="password" id="password" name="password" autocomplete="current-password" required>
```

### 允许粘贴密码

有些网站不允许将文本粘贴到密码输入中。

禁止粘贴密码会惹恼用户、鼓励使用易于记忆（因而可能更易被破解）的密码，并且据英国国家网络安全中心等组织称，实际上可能降低安全性。用户只有在尝试粘贴密码后才会意识到粘贴被禁止，因此禁止粘贴密码并不能避免剪贴板漏洞。
