# 隐私政策指南

## 何时需要隐私政策？

如果你的扩展符合以下任一情况，则**必须**提供隐私政策 URL：
- 处理个人或敏感用户数据（按 CWS 政策定义）
- 使用以下任一权限：`identity`、`cookies`、`webRequest`、`browsingData`、
  `history`、`bookmarks`、`topSites`、`<all_urls>` 主机权限
- 收集任何形式的分析或遥测数据
- 将任何数据传输到用户设备之外

所有扩展都**建议**提供隐私政策，即使不收集任何数据。这体现专业性，也能在审核人员标记你的扩展时避免延误。

## 托管位置

隐私政策必须位于可公开访问的 URL。可选方案：
- **GitHub Pages**：免费、受版本控制。在 `docs/` 分支中创建 `privacy.md`。
- **GitHub Gist**：快速简便。创建公开 gist 并链接到 raw URL。
- **项目网站**：如果有，添加 `/privacy` 页面。
- **Notion / Google Sites**：免费托管页面，URL 稳定。

避免托管在可能下线或变更的 URL 上。CWS 审核团队会检查该链接。

## 应包含的内容

### 最简政策（不收集数据）

如果你的扩展确实不收集任何数据，政策可以很短：

```
[扩展名称] 隐私政策

最后更新：[日期]

[扩展名称] 不收集、存储或传输任何个人数据或浏览信息。所有数据均保留在你的设备上。

本扩展不使用 Cookie、分析工具或第三方服务。

如有疑问，请联系 [邮箱]。
```

### 标准政策（收集部分数据）

如果你的扩展存储或传输数据，需涵盖以下内容：

1. **收集哪些数据** — 要具体。"用户偏好"不够。
   应写"你选择的主题偏好（浅色/深色）和保存的高亮颜色"。

2. **数据如何存储** — 仅本地存储？通过 chrome.storage.sync 同步？
   发送到服务器？

3. **为何收集数据** — 将每种数据类型对应到具体功能。

4. **第三方服务** — 如果使用任何 API（分析、认证等），列出名称
   并链接其隐私政策。

5. **数据共享** — 说明是否与第三方共享数据。如果是，与谁共享及原因。如果否，明确说明。

6. **数据保留** — 数据保留多久？用户能否删除？

7. **用户控制** — 用户如何访问、导出或删除数据？
   如果扩展有"清除数据"按钮，请提及。

8. **政策变更** — 说明如果做法变更会更新政策，
   以及如何通知用户。

9. **联系方式** — 隐私问题的邮箱或 URL。

### 模板

```
[扩展名称] 隐私政策

最后更新：[日期]

## 我们收集哪些数据

[描述收集的每种数据类型及需要它的功能。]

## 数据如何存储

[描述存储机制 — 仅本地、同步或服务器端。]

## 数据如何使用

[描述每个使用场景，对应到具体功能。]

## 第三方服务

[列出使用的任何第三方服务，链接其隐私政策。
如果没有，写明"本扩展不使用任何第三方服务。"]

## 数据共享

[说明是否共享数据。如果是，与谁共享及原因。]

## 数据保留与删除

[数据保留多久。用户如何删除。]

## 本政策的变更

[政策可能如何及何时更新。如何通知用户。]

## 联系方式

[隐私咨询的邮箱或支持 URL。]
```

## 常见错误

- **政策与数据披露表不一致**：CWS 数据披露表与你的
  隐私政策必须一致。如果表格写"不收集数据"但政策
  提到分析工具，你会被拒绝。

- **政策过于模糊**："我们可能收集一些数据"不可接受。要具体。

- **死链**：如果隐私政策 URL 返回 404，提交会被自动拒绝。
  提交前验证链接。

- **遗漏数据类型**：如果扩展使用 `chrome.storage.sync`，该数据会传到
  Google 服务器 — 需披露。如果发起任何 `fetch()` 调用，披露发送的内容。

- **缺少联系方式**：CWS 要求用户能就隐私问题联系到你。
  至少包含一个邮箱地址。
