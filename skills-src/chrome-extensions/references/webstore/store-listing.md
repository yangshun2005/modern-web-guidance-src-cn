# 商店信息填写技巧与常见拒绝原因

## 撰写有效的描述

### 简短描述（最多 132 字符）

简短描述会出现在搜索结果和分类页面中，是你的电梯演讲。规则：

- 以动词或扩展的功能开头：写"拦截所有网站上的广告"，而不是"广告拦截器"
- 要具体：写"将选中的文本翻译成 50 多种语言"，而不是"翻译工具"
- 自然地包含主要关键词
- 不要把字符浪费在"Chrome 扩展"上——用户已经知道了

**好的示例：**
- "一键保存文章以便稍后阅读。支持离线使用。"
- "将新标签页替换为显示天气和任务的极简仪表盘"
- "在任意网页上高亮和标注文本。可将笔记导出为 Markdown。"

**差的示例：**
- "Chrome 上最好的生产力工具！"（含糊，营销腔）
- "帮助你更好地做事的扩展"（什么都没说）
- "全新！惊艳的标签页管理器扩展工具应用，适用于 Chrome 浏览器"（关键词堆砌）

### 详细描述（最多 16,000 字符）

CWS 会剥离所有 Markdown 格式。请使用带换行的纯文本。结构：

```
[一句话：这个扩展是做什么的？]

功能
• 功能 1 — 简要说明
• 功能 2 — 简要说明
• 功能 3 — 简要说明

使用方法
1. 点击工具栏中的扩展图标
2. [下一步]
3. [下一步]

隐私
本扩展不收集任何个人数据。你的[数据类型]存储在本地设备上，
绝不会传输到任何服务器。

权限
• "读取和更改你访问的网站上的数据" — 用于[具体功能]。
  扩展仅在你[触发操作]时激活。

支持
发现 Bug？有建议？请发送邮件至 [email] 或在 [URL] 提交 Issue。

版本 [X.Y.Z] — [最新版本的简要更新日志]
```

### 实现细节规则

**绝不要描述扩展是如何构建的。** 潜在用户不是评估你技术栈的开发者——他们想知道扩展能为他们做什么。

从每一段文案中删除以下所有内容：

- Web API 名称：`MutationObserver`、`IntersectionObserver`、`Service Worker`、`Shadow DOM`、`IndexedDB`、`WebSockets`
- Chrome API 名称：`chrome.storage`、`declarativeNetRequest`、`chrome.scripting`、`offscreen document`
- 框架/库名称：React、custom elements、Lit、Webpack、TypeScript
- 架构描述："后台处理"、"事件驱动"、"声明式"

**把每一句实现描述转化为用户收益：**

| 修改前（实现） | 修改后（用户收益） |
|-------------------------|----------------------|
| "使用 MutationObserver 检测页面变化" | "浏览时自动检测新内容" |
| "使用 custom elements 和 Shadow DOM 构建" | "无缝运行，不影响页面样式" |
| "由 service worker 驱动" | "在后台静默运行" |
| "你的设置通过 chrome.storage.sync 同步" | "你的设置会在所有设备间同步" |
| "实现 declarativeNetRequest 进行过滤" | "拦截广告和跟踪器，不读取你的页面内容" |

### 为什么这个结构有效

1. **一句话开头** — 审核人员和用户都会扫视第一行。让它发挥作用。
2. **功能列表** — 用户会扫视功能。纯文本项目符号（•）渲染效果好。
3. **使用方法** — 减少支持请求，并证明扩展确实可用。
4. **隐私部分** — 预先打消用户对权限的顾虑。建立信任。
5. **权限说明** — 用户在安装时会看到权限警告。如果你在描述中
   解释了这些权限，他们中止安装的可能性就会降低。
6. **支持信息** — CWS 政策要求（"有意义的客户支持"）。
7. **最新版本说明** — 表明扩展在积极维护。

### 单一用途声明

此项在开发者仪表板中填写，不向用户展示。审核团队会仔细阅读。
它必须是一句话，描述扩展的狭窄用途。

**通过的示例：**
- "将网页中高亮的文本保存到本地阅读列表"
- "将新标签页替换为可自定义的仪表盘"
- "拦截网站上的 Cookie 同意横幅"

**被拒的示例：**
- "改善你的浏览体验"（太含糊）
- "生产力和组织工具"（太宽泛）
- "高亮文本、保存书签、管理标签页并拦截广告"（不是单一用途）

如果你的扩展做多件事，请聚焦主要功能。详细描述可以涵盖次要功能。

## 常见拒绝原因

### 1. 权限过多

**症状：**"你的扩展请求的权限超出了所需。"

**修复：**
- 用特定的主机模式替换 `<all_urls>`
- 如果你只需要在点击时访问当前标签页，用 `activeTab` 替换 `tabs`
- 移除未使用的权限
- 确保每个权限都有明确的理由

### 2. 单一用途缺失或不充分

**症状：**"你的项目没有单一、明确的用途。"

**修复：**
- 将单一用途字段重写为狭窄且具体的描述
- 如果扩展确实做了太多不相关的事情，考虑拆分它

### 3. 描述或功能具有误导性

**症状：**"你的扩展未提供所描述的功能。"

**修复：**
- 确保描述中列出的每个功能都确实可用
- 移除尚未构建的功能声明
- 除非可验证，否则不要使用最高级表述（"最好的"、"最快的"）

### 4. 隐私政策问题

**症状：**"你的扩展需要隐私政策。"或"你的隐私政策 URL 无法访问。"

**修复：**
- 将隐私政策托管在稳定、公开的 URL 上
- 确保它不在登录墙后面
- 确保它涵盖扩展实际收集的所有数据
- 使隐私政策与数据披露表单保持一致

### 5. 商标侵权

**症状：**"你的扩展未经授权使用了商标内容。"

**修复：**
- 不要在扩展名称中使用其他公司的名称（例如"YouTube Downloader"）
- 不要使用暗示关联的徽标或品牌颜色
- 使用通用术语："[网站]的视频下载器"可能没问题，但要查看该网站的条款

### 6. 代码可读性

**症状：**"你的扩展包含混淆代码。"

**修复：**
- 允许压缩；不允许混淆
- 如果使用打包工具（webpack、rollup、vite），确保不包含 source map，
  但输出是压缩的，而非混淆的
- 不要使用字符串编码技巧来隐藏代码意图

### 7. 远程代码执行

**症状：**"你的扩展执行远程托管的代码。"

**修复：**
- 将所有 JavaScript 打包到扩展包中
- 不要在运行时从 CDN 加载脚本
- 不要对远程内容使用 `eval()` 或 `new Function()`
- 从 API 获取 JSON 数据没问题；获取并执行 JS 则不行

### 8. 用户数据披露不匹配

**症状：**"你的扩展的数据使用情况与你的披露不符。"

**修复：**
- 审计每一处 `fetch()`、`XMLHttpRequest` 和 `chrome.storage.sync` 调用
- 记住 `chrome.storage.sync` 会将数据传输到 Google 的服务器
- 如果使用任何分析库（即使是自托管的），也要声明
- 如果将错误记录到外部服务，也要声明

## 被拒之后

当扩展被拒绝时：

1. 仔细阅读拒绝邮件——它会指明违反了哪项政策
2. 将拒绝原因和修复方案更新到 CHROMEWEBSTORE.md
3. 对扩展代码或商店信息进行所需更改
4. 对照发布前检查清单重新验证
5. 通过开发者仪表板重新提交
6. 注意：反复违反政策可能导致账号被封禁

## 审核时间线

- 首次提交：通常 1–3 个工作日，可能更长
- 现有扩展的更新：通常更快，往往在 24 小时内
- 加急审核：官方不提供；保持良好的记录会有帮助
- 延迟发布：你可以选择在审核通过后手动发布，
  从而控制发布时间。必须在批准后 30 天内发布。
